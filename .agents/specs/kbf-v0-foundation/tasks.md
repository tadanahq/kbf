- [x] `scripts/boundaries.go` + make target + self-test — Stretch goal, done ahead of schedule (this batch's brief invited it: "implement boundaries scan + self-test if time allows"). Own Go module (`scripts/go.mod`): a blocklist-plus-heuristics scanner (private filesystem paths, prices), `make boundaries` runs the self-test then the real scan against the repo. **Important design call, not in the original brief**: the production blocklist ships *empty*. `scripts/boundaries.go` is itself published to the public repo it scans, so writing a real client/internal-project name into it as a literal string would be the exact leak this tool exists to catch, the moment it's committed — a blocklist that documents what must stay private, in public, defeats itself. `scan()` takes the blocklist as a parameter specifically so the self-test can exercise the real mechanism with synthetic terms (`Example-Confidential-Co`) without the production list needing real entries to do it. The repo owner should add real terms directly, each with a comment on why, in a commit they review themselves — not something an agent should guess at from incidentally-visible context. Two bugs found and fixed while building this: (1) `go build ./...` on a package-main module with no `-o` silently writes an executable named after the directory into that directory (`scripts/scripts`), which then got scanned as binary garbage — fixed by adding a proper NUL-byte binary sniff (same technique `git`/`grep -I` use) rather than trusting extensions alone, and by gitignoring build output; (2) the self-test's own synthetic fixture strings (an example absolute path shaped like a personal machine's home directory, an example dollar amount) tripped the real repo-wide scan since they live in a committed file — excluded `scripts/boundaries_test.go` specifically, by identity, everything else (including every *other* test file) stays fully in scope; this very sentence hit the same trap once by naming the two literal example strings instead of describing their shape, caught immediately by `make boundaries` itself failing on its own capsule note. 7 tests, all green; `TestRealRepoIsClean` runs the production scan inside `go test` too, so it fails in the same place as everything else.
